Functions

                            
                            
Данный модуль необходим для тестирования отдельных функций Платежных API.

                            
                            

                                
                            

                            
                            
При переходе на вкладку Functions в модуле Navigator появляется возможность выбора функций в списке Available Functions.

                            
                            
Модуль Available Functions разделен на 6 зон: "Токены", "Общие функции", "Intents", "Consents", "Payments", "Accounts"

                            
                            

                                
                            

                            
                            
Рассмотрим интерфейс отдельно взятой функции на примере Domestic → POST /paymentConsents/domestic

                            
                            

                                
                            

                            
                            
Зона выполнения любой функции поделена на 4 подзоны:

                            
                            
    
                                
  1. Зона выполнения — в данной зоне имеется информация о названии роута, кнопка "Execute" для вызова метода.
    2. 
                                
  2. Зона тела запроса — в данной зоне должно находиться тело запроса, имеется кнопка "Format JSON", которая позволяет форматировать JSON документ в поле ввода.
    3. 
                                
  3. Зона тела ответа — в данной зоне находится тело ответа на запрос и статус результата работы приложения. Например, Status: success говорит о том, что запрос был успешно отправлен, отработал и был получен ответ.
    4. 
                                
  4. Зона заголовков — в данной зоне находятся обязательные и необязательные заголовки, которые могут присутствовать в методах Платежных API. Для добавления (выбора) заголовка необходимо перевести чек-бокс в активное состояние:
                                    
      
                                        
    • x-fapi-interaction-id, x-idempotency-key — генерируются случайно;
      • 
                                        
    • x-fapi-customer-ip-address — получает актуальный IP-адрес;
      • 
                                        
    • x-fapi-auth-date — получает актуальную дату;
      • 
                                        
    • Content-Type: application/json — в активном состоянии получает значение "application/json;charset=utf-8", в неактивном — "application/xml;charset=utf-8";
      • 
                                        
    • x-api-key — получает значение из конфига. Если находится в активном состоянии — забирает значение apikey из конфига, если в неактивном, то забирает значение access_token;
      • 
                                        
    • privateIdentification и organisationIdentification — необходимы для идентификации типа бенефициара в том случае, если отсутствует атрибут data.initiation.debtor.
      • 
                                    
    
                                
    5. 
                            

                            
                            
GET, DELETE методы

                            
                            
Во всех методах с GET/DELETE типами HTTP запросов нет тела запроса. Вместо этого используется строка URL для идентификации метода. Например:

                            
                            

                                
                            

                            
                            
Будет произведен вызов метода GET /paymentConsents/domestic/{domesticConsentId}, где domesticConsentId = 88cfcb0e-78ef-4636-bb4b-11c910510e79.

                            
                            
Для DELETE методов тело запроса и способ вызова аналогичны:

                            
                            

                                
                            

                            
                            
Токены

                            
                            
При вызове методов Платежных API возникает возможность использования разных потоков авторизации. В данном приложении реализовано 4 метода для получения токенов: GET PISPtoken, QPISPtoken, TPEtoken, OBtoken. Для получения Bearer-токена используется блок "Токены".

                            
                            

                                
                            

                            
                            
Логин и пароль, необходимые для получения токенов, берутся из конфига.

                        

                    


                    
                    

                        

                            
Sequence

                            
                            
Данный модуль необходим для выполнения "Цепочек запросов".

                            
                            
Модуль разделен на 5 зон:

                            
                            
    
                                
  1. Зона типа платежа — в данной зоне находится 8 радиокнопок, которые представляют 7 типов платежей и согласия на счета. При проведении "цепочки запросов" может быть выбран только 1 тип платежа.
    2. 
                                
  2. Зона выбора шагов — в данной зоне присутствует вариант выбора этапов, необходимых для проведения платежа:
                                    
      
                                        
    • createConsent — этап, отвечающий за создание согласия;
      • 
                                        
    • authoriseConsent — этап, отвечающий за авторизацию согласия;
      • 
                                        
    • createPayment — этап, отвечающий за создание платежного указания.
      • 
                                    
    
                                    
    Внимание! При выборе этапа authoriseConsent необходимо также выбрать этап createConsent, а при выборе этапа createPayment должны быть активны два предыдущих этапа.
    
                                
    3. 
                                
  3. Зона тела запроса — в данной зоне должно находиться тело запроса, имеется кнопка "Format JSON", которая позволяет форматировать JSON документ в поле ввода "тело запроса".
    4. 
                                
  4. Зона заголовков — в данной зоне находятся обязательные и необязательные заголовки, которые могут присутствовать в методах Платежных API. Для добавления (выбора) заголовка необходимо перевести чек-бокс в активное состояние:
                                    
      
                                        
    • x-fapi-interaction-id, x-idempotency-key — генерируются случайно;
      • 
                                        
    • x-fapi-customer-ip-address — получает актуальный IP-адрес;
      • 
                                        
    • x-fapi-auth-date — получает актуальную дату;
      • 
                                        
    • Content-Type: application/json — в активном состоянии получает значение "application/json;charset=utf-8", в неактивном — "application/xml;charset=utf-8";
      • 
                                        
    • x-api-key — получает значение из конфига. Если находится в активном состоянии — забирает значение apikey из конфига, если в неактивном, то забирает значение access_token;
      • 
                                        
    • privateIdentification и organisationIdentification — необходимы для идентификации типа бенефициара в том случае, если отсутствует атрибут data.initiation.debtor.
      • 
                                    
    
                                    
    Внимание! Хидеры privateIdentification и organisationIdentification могут быть переданы только для согласий на проведение платежа
    
                                    
    Внимание! При выполнении "цепочек запросов" необходимо выбирать заголовки, нужные для работы методов "создания согласия", также необходимо использовать заголовок Content-type: application/json.
    
                                
    5. 
                                
  5. Зона тела ответа — в данной зоне находятся тела запросов/ответов для методов, выполнение которых необходимо при выполнении "цепочки запросов", и статусы выполнения каждого отдельного метода.

Configuration

                            
                            
Данный модуль необходим для настройки конфига приложения.

                            
                            

                                
                            

                            
                            
alg

                            
Идентификатор криптографического алгоритма ЭЦП, используемого для защиты JWS. Значение RS256 можно использовать в рамках данного экземпляра онлайн-спецификации исключительно в тестовом режиме, для соответствия требованиям СПР 6.02-2-2022 должны быть использованы значения BIGNS128 или BIGNS192 или BIGNS256 согласно "Вариантам алгоритмов выработки и проверки ЭЦП".

                            
                            
typ

                            
Тип сериализации: JOSE - компактная сериализация.

                            
                            
baseUrl

                            
префикс имён критичных частных

                            
                            
Подробнее с информацией можно ознакомиться на сваггере: {url_swagger}/#XJWSignatureSigningPH

                            
                            
url_kc

                            
URI сервера авторизации Keycloak

                            
                            
url_swagger

                            
URI сервера, который будет принимать запросы для вызова методов ПА

                            
                            
client_id_pisp, client_secret_pisp, client_id_qpisp, client_secret_qpisp, client_id_tpe, client_secret_tpe, client_id_dbo, client_secret_dbo

                            
Логин и сикрет клиента для соответствующего потока авторизации. Разберем на примере client_id_dbo и client_secret_dbo. Данные логин и сикрет нужны для авторизации по потоку OBclientCredentials. Пусть у нас имеется взаимодействие с ДБО ЮЛ DigitalChannels. Тогда в кейклоке будет создан и настроен клиент digitalChannels

                            
                            

                                
                            

                            
                            
В таком случае в проперть client_id_dbo указывается "digitalChannels", а в client_secret_dbo указывается сикрет из кейклока для данного клиента "rvDMLEf5Njz6L5BGpst4dLP1hMrBWxEV"

                            
                            
Подробнее ознакомиться с потоками авторизации можно по ссылке {url_swagger}#section/Authentication

                            
                            
apikey

                            
уникальный идентификатор, предоставляющий доступ к SC-MAP Пользователем API первого типа. Пользователь API первого типа, может получить Apikey, использование которого аутентифицирует и авторизует Пользователя API первого типа в системе. Apikey выдается через SC-MAP, являющийся в данном процессе Сервером авторизации Поставщика API. После создания и авторизациии долгосрочного согласия в системе SC-MAP Пользователю API первого типа выдается Apikey, который используется далее для идентификации и авторизации запросов Пользователя API первого типа указанием в запросах HTTP-заголовка x-api-key вместо HTTP-заголовка Authorization.

                            
                            
client_otp

                            
OTP клиента, который будет использоваться при формировании имитовставки для спец. части согласия при его авторизации.

                            
                            
mobile_number

                            
номер мобильного телефона клиента, который будет использоваться при формировании имитовставки для спец. части согласия при его авторизации

                            
                            
subjectKeyIdentifier

                            
Идентификатор ключа субъекта СДБО

                            
                            
password

                            
Пароль к контейнеру ключа субъекта СДБО

                            
                            
EDSsignatureSubjectKeyIdentifier

                            
Идентификатор ключа субъекта.

                            
                            
EDSsignaturepassword

                            
Пароль к контейнеру ключа субъекта.

                            
                            
Внимание! Проперти EDSsignatureSubjectKeyIdentifier и EDSsignaturepassword используются только в случае авторизации согласия с ЭЦП. Подробнее можно ознакомиться на сваггере {url_swagger}#EDSspecialPart

                        

                    


                    
                    

                        

                            
Начало работы

                            
                            
Для начала работы с Платежными API необходимо создать федерацию ДБО в Keycloak.

                            
                            

                                
                            

                            
                            

                                
                            

                            
                            
Обязательные поля:

                            
    
                                
  • Apikey и FederationURI предоставляет СДБО.
    • 
                                
  • accept - значение по умолчанию "application/json;charset=utf-8"
    • 
                                
  • accept-language - значение по умолчанию "ru"
    • 
                                
  • Batch Size - значение по умолчанию "1000"
    • 
                                
  • Timeout For Connecting to the Service - значение по умолчанию "5000"
    • 
                                
  • Timeout for Callig Service Methods - значение по умолчанию "5000"
    • 
                            

                            
                            
При нажатии на Save - должно появиться "зеленое" сообщение "Success! The provider has been updated."

                            
                            
Внимание! Если вместо "зеленого сообщения" получаем "красное" сообщение - можно проверить вызов методов ДБО "руками" с нод карафов curl -kiv -X GET -H "Content-type: application/json;charset=utf-8" -H "x-api-key: {apikey}" {dbo_host}:{dbo_port}/ibservices/OB/digitalChannels/users - Данный пример для ДБО digitalChannels
